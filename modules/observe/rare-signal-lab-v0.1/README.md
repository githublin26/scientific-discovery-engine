# Rare Signal Discovery Engine v0.1

A runnable, deliberately small research PoC for **early warning of synthetic semiconductor process excursions**. All observations are generated locally. No Merck, TSMC, customer, or proprietary data is included or required. No production decisions, hardware controls, Transformers, or agent swarms.

## Scientific question

Can weak, correlated measurements identify an impending excursion before univariate SPC alarms, at an acceptable false-alarm rate?

H0: conventional SPC is equal or better at early warning under the same false-alarm constraint. H1: multivariate inference improves event recall and lead time without exceeding that constraint. Synthetic success supports this statement only for the specified simulator; it does not establish semiconductor validity or domain transfer.

IceCube reconstructs physical events from distributed photon observations. Its [2026 directional reconstruction research](https://icecube.wisc.edu/news/research/2026/05/new-machine-learning-method-improves-icecubes-estimation-of-neutrino-direction/) uses transformer-encoded normalizing flows to estimate directional posterior distributions; see the [original paper](https://arxiv.org/abs/2604.19846) and [official implementation](https://github.com/icecube/tnf_paper). The transferable principle explored here is **combine weak evidence, express predictive uncertainty, and validate the resulting decisions**. This repository does not reproduce IceCube, estimate a neutrino posterior, use its data, or prove that its architecture transfers. A calibrated binary forecast is a much simpler object than a physical event posterior. Calibration assesses empirical probability reliability, not epistemic uncertainty or causal understanding.

## Dataset and assumptions

Seven sensor-like measurements: oxygen, water, two particle bins, pressure drop, assay and temperature. Units, scales, distributions and limits are illustrative; particle measurements are continuous proxies, not physical count models. Each row includes lot/run identifiers, timestamp, tool ID, batch age, event onset, scenario and labels. Tool IDs and batch age are metadata, not predictors. Timestamps are local synthetic clocks; runs are independent simulation replicates, not one chronological fab history.

The generator uses serially correlated noise and shared disturbances. Run scenarios are sampled independently: 70% noise, 20% slow precursor, 10% obvious excursion. Onset is externally scheduled at lot 75–105, independent of measured SPC crossings. Event runs have an oxygen step of five baseline units at onset. This makes the endpoint observable without defining ground truth using the evaluated SPC algorithm.

* **Obvious:** abrupt oxygen step with no designed precursor. Early prediction should be difficult; Shewhart should detect the onset.
* **Slow:** the five first channels drift together over the preceding 12 lots, from 0.2 to 1.8 baseline units. Individual observations can cross limits because random noise is unbounded; this is not a guarantee that every precursor is below 3 sigma.
* **Noise:** no excursion, including shared and serial disturbances to challenge false-alarm control.

`--signal-strength 0` removes the precursor ramp while retaining the event endpoints and labels. This is a negative control: apparent early warning should collapse toward chance. All scenarios also appear separately in `metrics.csv`; do not hide the obvious scenario's expected early-warning failure by reporting only pooled results.

## Protocol and leakage prevention

Four independent sets of whole runs use seeds `10 * experiment_seed + {0,1,2,3}`:

1. Train: learn models and Phase-I SPC means/standard deviations from the first 50 training lots per run, before all designed ramps/events.
2. Calibration: fit a separate sigmoid mapping from each model's scalar score to `P(excursion in next 12 lots)`.
3. Validation: select the score threshold maximizing positive-lot recall under a default budget of **one false alarm per 100 normal eligible lots**. Ties prefer fewer false alarms and then a higher threshold. An above-maximum threshold permits no alerts.
4. Test: freeze all fits and thresholds, then report metrics. The validation budget is not a guarantee of the realized test rate.

Features are current measurements, trailing five-lot means and five-lot changes (21 dimensions). They include the current completed lot, never future observations; windows reset per run. First ten lots are warm-up. Prediction metrics exclude onset and post-event lots. Ground-truth onset, target, scenario, lot ID and labels never enter model features. This is an independent-run holdout, not validation on unseen tools or a chronological deployment study.

## Baselines

| Model | Score / training |
|---|---|
| Shewhart | Maximum absolute training-normalized sensor deviation; fixed 3 sigma and validation-budget variants |
| EWMA | Per-run recursion, lambda 0.2, maximum absolute normalized EWMA; asymptotic variance factor, fixed 3 sigma and budget variants |
| Isolation Forest | Unsupervised fit on training negative lots; negative normality score |
| Gradient Boosting | 70 shallow trees, supervised forecast target |
| Logistic regression | Standardized linear multivariate forecast, simplest probability-aware model |

Every scalar score receives independent sigmoid calibration, including SPC scores. The main threshold operates on the original score; calibration does not change alarms. SPC-derived probabilities mean forecast risk, not the probability that a control limit was exceeded. Fixed EWMA limits use a steady-state approximation; multiplicity and temporal correlation mean a nominal 3-sigma chart is not a prescribed overall false-alarm rate. Budget variants make a fairer operational comparison. Logistic regression is the simple uncertainty-aware candidate; no ensemble uncertainty claim is made.

## Metrics and artifacts

Outputs per seed: four raw split CSVs (including `calibration.csv`), `manifest.json` with dataset hashes/configuration/versions, `predictions.csv`, `metrics.csv`, `events.csv`, and `reliability.csv`. Top-level `summary.csv` holds pooled metrics per model and seed.

* **Lot precision / recall:** alerts in the 12 lots strictly before onset are true positives. Alerts outside that window are false positives, even if an event occurs much later. Zero alerts give precision zero by convention.
* **False alarms / 100 normal lots:** false alerted eligible lots divided by eligible target-negative lots, times 100. Repeated alerts count individually; this is not an alarm-episode rate.
* **Excursion recall:** fraction of event runs with at least one alert in their 12-lot early window. No events gives null.
* **Lead time:** onset minus first alert lot within that window. Median is conditional on detected events; always interpret alongside event recall. Misses remain null in the event table.
* **Paired gain versus SPC:** candidate lead minus fixed Shewhart lead, using Shewhart's first alert in the same window **including onset**. Both must have an alert; report paired sample size, never replace misses with invented lead times. Negative gains are allowed. This diagnostic uses fixed SPC, while operational comparison should use budget variants.
* **Probability calibration:** Brier score, log loss and ten equal-width-bin expected calibration error (ECE). `reliability.csv` supplies bin counts, predicted risks and observed fractions. Empty bins are null. Brier is sensitive to rare-event prevalence and ECE depends on binning; neither alone establishes useful warning.

## Falsifiable interpretation

Before inspecting a new experiment, use this exploratory gate: on the slow scenario, logistic or boosting should beat **both budget-matched SPC baselines** in excursion recall and detected-event median lead across all three specified seeds, while each candidate's realized false alarms stay <=1 per 100 normal lots. Compare calibration against a constant forecast using the calibration-set prevalence; use the exported labels/probabilities for this audit. The no-precursor control should remove the advantage. Failure on any part means H1 is **not supported by this gate**. This stringent gate is an explicit research convention, not a formal statistical hypothesis test; no p-values or causal conclusions are claimed. Never promote a model using the test results to retune thresholds.

The assessment command audits that gate without retuning; its negative-control check operationalizes loss of advantage as lower slow-scenario recall, not a statistical chance test. It uses the default budget of 1; manually audit any experiment using a different budget. The checked-in `example_results` contains compact verification artifacts and a candid interpretation. Full raw data/predictions are regenerated by the commands above. Tests verify deterministic generation, target timing, causal features, run-boundary resets, threshold budget, hand-computed metric denominators/lead time, calibration-bin endpoints, train-only SPC fitting and deterministic end-to-end output.

## Limits and scope

The simulator embeds patterns that supervised models can learn. Real fabs have missing measurements, delayed assay availability, process changes, maintenance, cross-tool shifts, competing events and uncertain labels. Here every sensor is assumed available at the end of its lot, including assay; delay would require a new availability-aware experiment. Event prevalence is deliberately enriched; real rarity can sharply reduce precision and change calibration. Runs contain at most one event; there are no cooldowns, intervention effects, missingness handling, persistence, serving endpoints or operational qualification. More architectures are unjustified until simple models fail under a defensible benchmark and real-world validation is available.
